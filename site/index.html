How it works when

When you ship the site

  1. 1

    Install it and run init

    One dev dependency with no runtime dependencies. init sets up the Studio beside next dev or vite; init --share adds share links for any static host and, on GitHub, the workflow that turns them into pull requests. 

    $ npm i -D livelocale
$ npx livelocale init

# share links on any static host, plus the GitHub workflow
$ npx livelocale init --share
  2. 2

    Your team fixes the text. You review a pull request.

    Whoever spots the wrong text fixes it on the site and presses Send. You get a pull request in your own repository, with every change as a JSON diff. This one is real: pull request #2 in Araby99/tidewell.

  3. 3

    CI catches what was never translated

    npx livelocale check --hardcoded runs in GitHub Actions or any CI and fails the build on text that never went through translation.

    Here it read a cut of the Tidewell pricing hero: the demo button was typed straight into the JSX and the Arabic note was left in English, so it exits 1 before either ships.

When you fix the text

  1. 1

    Open the link your developer sent

    It opens the real site with the Studio around it. No account, no git, nothing to install.

  2. 2

    Hold Alt and click the wrong text

    The editor opens on that exact string, showing the text it will replace. Nothing to search for, nothing to describe in a screenshot.

  3. 3

    Type the fix in any language, then press Send

    Switch to Arabic and the page turns right to left; type ابدأ تجربتك المجانية into the button that had no Arabic yet. Send hands your developer one link, and it becomes their pull request.

Works where you already are

Next.js, Vite, React and any static host. One-click pull requests on GitHub; on any other git host, npx livelocale apply <link> --pr.
